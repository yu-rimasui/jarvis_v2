# 共通ルール

- 変更前に、対象の既存コード・テスト・設定と既存の命名規則を確認する。
- 目的を満たす最小範囲だけを変更し、無関係な整理や抽象化を混ぜない。
- コードは Package by Feature を維持し、Feature境界と定義済みの依存方向を守る。
- 技術的な共通処理は `core` に、Feature固有のユースケースと判断は各Featureに置く。
- 将来の可能性だけを根拠に、分散基盤、汎用フレームワーク、形式的な層を導入しない。
- 認証情報、個人情報、会話本文、記憶の内容などをコード・fixture・ログへ残さない。
- 実装とテストの期待値を同時に見直し、変更した振る舞いと検証内容を一致させる。
- 既存の設計パターンが本ルールに反しない限り、それを優先して一貫性を保つ。
- 完了時は変更内容、実行した検証、その結果、未実行の検証と残るリスクを明確に報告する。
