# インフラストラクチャ

Docker Composeは、Jarvisをローカルで再現可能に起動・検証するために使う。少なくとも次の責務を分離する方針とする。

```text
app
postgres
vector-db
```

- `app` はアプリケーション実行、`postgres` は構造化データ原本、`vector-db` は意味検索インデックスを担う。インフラ接続や起動待ちの詳細をFeatureへ混在させない。
- 環境変数は設定の注入に使う。`.env` はローカル値用として追跡せず、`.env.example` には秘密でない変数名・説明・安全な例だけを置く。
- APIキー、接続文字列の認証部分、個人データはリポジトリ・イメージ・ログへ保存しない。
- 各依存サービスには必要に応じたhealthcheckを置き、起動依存は「プロセス開始」ではなく利用可能状態を意識して定義する。
- 永続化が必要なデータは明示的なvolumeで保持し、削除・初期化の影響範囲を理解できる構成にする。
- DB初期化とmigrationは再現可能な手順にし、アプリケーションコンテナへ隠れた手作業を持ち込まない。
- ログはローカル障害の診断に必要な最小限とし、secret・会話・記憶本文を出力しない。
- 外部サービス接続は明示的な設定と利用者の許可を要する。本番固有の監視、オートスケール、複数環境、複雑な配備基盤は、現段階で先取りしない。
